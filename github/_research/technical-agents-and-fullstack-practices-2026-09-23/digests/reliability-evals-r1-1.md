## Notes for synthesis
- **Simplest memory for a hackathon:** keep the full conversation in your own app state, or use a framework session (OpenAI `SQLiteSession`, Anthropic `BetaLocalFilesystemMemoryTool`). Both are $0 and add no dependency. Mem0's free tier caps retrievals at 1k/month, which is fine for a demo but tight for load testing. I did not check Letta, Zep or the LangGraph store this round.
- **Observability pick for $0:** Langfuse gives the most free units (50k units/mo, OSS, self-hostable) and is now owned by ClickHouse, which says it stays open source. LangSmith's free plan is 5k traces and 1 seat, which is limiting for a team. Braintrust's free plan allows unlimited users but keeps data 14 days. Helicone is in maintenance mode after the Mintlify deal, so don't recommend it for new builds.
- **Reliability rules backed by sources:** cap the loop (`max_turns` / `max_iterations`) and never rely on a default. Rely on SDK auto-retry, or raise it, for 429/529. Stream every response. Keep each serverless call under 300s on Vercel Hobby, and break long agent runs into steps or move them to a background worker. Put stable system prompts and tools first so they get cached (5-min TTL). Know that a spend-cap 429 never recovers, so a spend cap works as a budget kill-switch.
- **Eval practice for 24–48h:** about 20–50 cases from real failures, binary pass/fail, and read the transcripts. Only add an LLM judge if you check it against about 20+ of your own labels. The Anthropic and Hamel sources agree.
- **Security:** use the lethal-trifecta test as the one-line rule. Map it to OWASP ASI01 (goal hijack) and ASI02 (tool misuse). Require human approval for destructive tools. Restrict memory paths.
- **Temperature/seed caveat:** in the errors page I saw that the latest Claude models always have thinking on and reject forced tool_choice. I did not verify whether they accept `temperature`, so don't recommend "temperature 0 for determinism" without checking. The eval guidance assumes nondeterminism anyway.
