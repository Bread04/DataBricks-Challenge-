5. The 2026-07-28 spec makes the core **stateless**. It removes the `initialize`/`initialized` handshake and the `Mcp-Session-Id` header, so state now goes in explicit handles returned by tools. It also adds `Mcp-Method`/`Mcp-Name` routing headers and cacheable list results (`ttlMs`, `cacheScope`). | https://blog.modelcontextprotocol.io/posts/2026-07-28/ | MCP project | 2026-07-28 | accessed 2026-09-22 | high | official
6. 2026-07-28 also brings: **Multi Round-Trip Requests**, where a server returns `resultType: "input_required"` to ask for user input mid-call instead of holding a stream open. **Authorization hardening**: RFC 9207 issuer validation is required, clients move from Dynamic Client Registration to Client ID Metadata Documents, and credentials are bound to the issuing AS. A formal **extensions framework** covers Tasks (`io.modelcontextprotocol/tasks`), MCP Apps and Enterprise Managed Authorization. | same | MCP project | 2026-07-28 | accessed 2026-09-22 | high | official
7. **Deprecated in 2026-07-28:** Roots, Sampling and Logging (at least a 12-month window before removal) and the legacy HTTP+SSE transport. A formal Active/Deprecated/Removed lifecycle applies. Tier-1 SDKs (TS, Python, Go, C#) are updated and backward compatible; the Rust SDK is in beta. | same + search snippet | MCP project | 2026-07-28 | accessed 2026-09-22 | high | official

## Practical guidance (derived)

- **Default path for a hackathon team:** start from the official Claude Code plugin marketplace (F15). Plugins like github, supabase, vercel, sentry and linear come with MCP servers already configured, so you skip hand-editing JSON. Where a vendor has no plugin, use `claude mcp add --transport http <name> <vendor-url>` and authenticate with `/mcp` OAuth (F9, F11).
- **Share config through git:** commit `.mcp.json` at project scope and keep secrets in `${VAR}` expansions, never inline (F10). Commit `.claude/settings.json` with `extraKnownMarketplaces` + `enabledPlugins` so teammates get the same plugins after trusting the folder (F17). Each member still has to install externally sourced plugins once.
- **Discovery order by trust:** (1) claude-plugins-official and claude.ai/directory, which Anthropic curates or reviews (F15, F18); (2) the Official MCP Registry, which carries namespace metadata but is not a safety review (F1–F2; its curation level was not verified this run); (3) Docker MCP Catalog, whose containerized, "verified" images isolate local servers (F20); (4) Glama, Smithery, PulseMCP and mcp.so, for discovery only. Vet the repo, prefer vendor-official servers, and assume unmaintained code or SSRF risk (F21).
- **Prefer remote HTTP servers.** Avoid SSE-only servers: the spec deprecates SSE and Claude Code marks it deprecated (F7, F9). For local servers, prefer Docker-packaged or vendor-published stdio packages.
- **Context budget:** leave tool search on, since it is the default (F13). If a server dumps large results such as DB schemas, raise `MAX_MCP_OUTPUT_TOKENS` rather than disabling tool search (F12).
- **If you are building an MCP server during the hackathon,** target spec 2026-07-28: stateless design, no reliance on sessions, CIMD-style auth. Avoid the deprecated Sampling, Roots and Logging features (F5–F7). Tier-1 SDKs stay backward compatible, so older clients keep working.
- **Claude Desktop users** can install local servers as `.mcpb` bundles with one click (F19). Claude Code users just use `claude mcp add` or plugins, and can import existing Desktop config with `claude mcp add-from-claude-desktop` (F9).
